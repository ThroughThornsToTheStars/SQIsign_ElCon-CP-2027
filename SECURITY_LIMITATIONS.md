# Security review status

**Cache exposure in the secret backend.** In the measured x86-64 Nettle 4.0 library, the compression path reached by Streebog update uses state-derived bytes to index tables. The code at 0x27fa5 XORs a state word with input, 0x27fe7 extracts the low byte and 0x27fee reads a word at table_base + 8·byte. The HMAC key schedule and the 63-byte PRNG inputs include secret data. A local observer capable of learning memory-access patterns is relevant. Source-level branches in sqi_stream_read depend on request length, public counter and cursor. These observations do not establish constant-time execution. No leakage magnitude or practical recovery was measured. See the binary digest and excerpts in results/security.txt. A side-channel-resistant implementation and independent leakage assessment are prerequisites to deployment in this threat model.

**Secret lifetime.** The root, derived K, remaining block bytes and hash temporaries are sensitive. Clear the caller-owned domain and the thread root on all exit paths. The upstream wipe prevents normal dead-store removal, with no guarantee over registers, spills inside libraries, swap, core dumps or copies. Reading root or domain state allows regeneration of earlier and future bytes of that operation. Fresh OS entropy at the next operation is necessary for recovery. Forking or snapshotting live state can duplicate a stream. Test seeds and vectors are public and unsuitable for use as secrets.

**Security assumptions.** Public H with a domain prefix and truncation preserves the scalar range. A random-oracle/QROM argument for the adapted scheme requires separate analysis. Generic collision work for an n-bit truncated digest is only about 2^(n/2) classical queries; this alone is not the signature forgery complexity. HMAC key separation assumes PRF behavior under this use. The counter generator needs indistinguishability across many related secret inputs and domains. Published constraints on a mechanism, a 384-bit root and passing KATs do not prove those assumptions or imply 384 bits of actual entropy. The profile cap is an engineering bound, not an evaluated lifetime. The 384-bit root also puts an upper bound on exhaustive-search cost (idealized square-root quantum search), relevant when discussing the largest parameter set. The baseline also requests 48 bytes.

**Failure propagation and interoperability.** The byte reader rejects counter overflow without partial output. Several higher-level rejection loops treat sampling failure as retry; no end-to-end termination guarantee at artificial exhaustion. A normal invocation would have to consume almost 256 GiB in one domain to reach it. No upstream arithmetic was patched to change this policy. Identical root/domain clones replay exactly and must never be used to introduce independence. Keys and signatures have no profile marker; select the expected verifier externally. Changing a local signing PRNG does not authenticate the PRNG choice to a verifier.

**Coverage.** Key generation and signing use retry loops and other variable-time upstream operations. The original authors discuss implementation and parameter-security uncertainty. No new proof of EUF-CMA, QROM reduction, side-channel resistance, certification, assessment of OS entropy, or upper bound on leakage is provided. [SQIsign 3.0, chapters 1 and 8](https://sqisign.org/spec/sqisign-20260901.pdf)

## Backend audit on the reviewer build

The packaged ELF is Arch nettle 4.0-1. Its SHA-256 matches the original benchmark host record. RUSSIAN_PRNG with public regression index 1 resolves all six Streebog and HMAC entry points to libnettle.so.9. The ELF uses lazy binding. These symbol resolutions establish the API path for this signing experiment. Inside Nettle, the release source routes HMAC key setup and finalization through Streebog. Its LPSX transformation uses state-derived byte indices into eight tables of 256 words. The first padded 63-byte PRNG input includes K in bytes 15–62, so the final compression of that block transforms secret-dependent bytes even when the update initially buffers everything. Source and machine code therefore violate secret-independent address access for this binary. With public Fiat–Shamir inputs the same address dependency concerns public values. [Fresh linkage and disassembly](results/ieee-audit/nettle-binary.txt) · [Reproduction](research/inspect-nettle.sh) · [4.0 compression](https://github.com/gnutls/nettle/blob/bf13ee9e5024014cfa6d2fc097923afe087e63ba/streebog.c#L1141) · [4.0 HMAC](https://github.com/gnutls/nettle/blob/bf13ee9e5024014cfa6d2fc097923afe087e63ba/hmac-streebog.c#L43)

A co-resident observer sharing caches could in principle distinguish some address patterns. The amount of information observable under scheduling noise, how often a secret is reused, and the feasibility of recovery remain unmeasured. A remote timing observer, power/EM measurements and fault injection are separate models. Runtime dependency resolution and ordinary benchmarks supply no leakage magnitude. This host lacked Valgrind/ctgrind. No key-recovery or leakage experiment is reported.

Botan offers an alternative Streebog compression path with register-based instructions on supported CPUs. Its actual Streebog dispatch at the linked revision requires both AVX-512 and GFNI. The i7-4770HQ reports AVX2 and lacks these two features. Falling back to Botan's portable table code would retain the address channel. A viable experiment on another machine would enforce the selected provider for all keyed hashes, test both digest and HMAC against the independent vectors, inspect the executed binary and evaluate leakage with the specified threat model. A Boolean circuit for the common substitution box is another candidate building block. Its integration would also require validation of linear layers, additions, buffering, padding and the HMAC key schedule. Neither path has been qualified as a replacement on this host. All recorded measurements use Nettle for the adapted symmetric components.
