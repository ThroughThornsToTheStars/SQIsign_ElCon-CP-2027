# Security and compatibility argument for profile revision 1

This analysis applies to the reference integration at `7392c66e3e77acd36ee9531e8f965ef0d7bd0c0e` and the same primitive code in the reviewer branch. The four profiles form a two-factor experiment. Only the challenge algorithm participates in verification. Applications that support both algorithms must bind the expected profile to their key or protocol policy. The encoding has no algorithm identifier. [Wire definition](CRYPTO_PROFILE.md) · [Call map](ARCHITECTURE.md)

## Public challenge

For a set with challenge length n = 16, 24 or 32 octets, the input consists, in order, of the ASCII label `SQIsign3-FS-Streebog512-v1`, one octet containing n, ASCII `SQI`, encoded public key, encoded commitment coefficient A, and the entire message. Strings exclude C terminators. The public key contains the normalized Montgomery coefficient and its hint. Both field elements use the upstream real-then-imaginary, fixed-width, little-endian representation. Key sizes are 83/129/169 and commitment sizes 82/128/168 octets. The message can be empty. At a fixed n there is just one split of these bytes into fields. This establishes unique field boundaries for encoded inputs. Any equivalences of mathematical curve representatives or validation of adversarial keys belong to the original codecs and verifier. Verification reconstructs the commitment and passes it to the same helper. [Integration](src/verification/ref/lvlx/common.c) · [Digest](src/common/generic/research_profile.c)

Take the first n digest octets in API order and decode as a little-endian unsigned integer. The upstream zero-initialized scalar, limb conversion and challenge-to-kernel operation are retained. Thus the function ranges over integers 0 through 2^(8n)−1 with the required width. Uniformity of these values over adversarial transcripts requires a hash assumption. Distinct fixed labels, set widths and input lengths separate the challenge transcript from the 63-byte counter input and from HMAC initialization in this application. Cross-application use requires separate review.

For an ideal t-bit output, the classical birthday search for any pair colliding costs order 2^(t/2). For a fixed independent target the success probability of q independent trials is at most q/2^t. A pair of arbitrary colliding byte strings need not be valid commitment transcripts for the attacked key or yield a valid response on a new message. These estimates are different experiments from chosen-message forgery. In particular the birthday cost at t = 128 does not establish a 64-bit signature security level.

Theorem 8.1.7 analyzes SQIsign in the classical random oracle model with bounds depending on the number of signing and oracle queries, hint-assisted OneEnd hardness, hint indistinguishability and distributional terms. The sampler and challenge space enter that analysis. Remark 8.1.8 discusses quantum queries in an algebraic isogeny model with extra restrictions on the adversary. A fixed truncated digest is a concrete instantiation. Collision resistance by itself does not simulate the programmable oracle used in the proof. No reduction for this Streebog instantiation or concrete quantum loss bound is available here. [SQIsign 3.0 §§3.3, 8.1–8.2](https://sqisign.org/spec/sqisign-20260901.pdf)

## Secret streams

Key generation and signing each request a 48-octet root S from the upstream provider. The Linux system build relies on fresh OS cryptographic randomness. The test build deterministically draws S from the upstream AES-based test provider. A 384-bit field bounds possible seed entropy from above. Cloning process state, repeated experimental seeds and failures at the entropy boundary invalidate independence. No entropy estimate for the host was made. [Entropy interface and domain lifetime](src/common/generic/prng.c)

For ASCII d in {key, com, res, def}, K is the first 48 octets of HMAC-Streebog-512(S, ASCII("SQIsign3-PRNG-v1") || d). The 15-octet low field consists of LE32(i) followed by eleven zero octets. Append K to that field and hash the resulting 63 bytes with Streebog-512. Start i at one. Concatenate full digests in API order and serve consecutive bytes through the cached cursor. A read of zero bytes preserves the cursor. After 64(2^32−1) bytes the stream is exhausted. The length check precedes writes and counter updates. Repeating S,d repeats all bytes. A copied active context yields the identical suffix. Signing can consume different quantities of random data on different arithmetic paths. A possible game argument first replaces domain derivation with independent 384-bit strings for distinct labels under each fresh root, then replaces each bounded counter stream with ideal random blocks. It needs multi-user bounds, probabilities of root/key repeats and a joint argument for HMAC, the counter inputs and the public challenge. Domain labels alone do not establish that argument. In the idealized uniform-key model, D derived keys have collision probability at most D(D−1)/2^385. A repeated root and label deterministically repeat an entire stream. No new entropy is introduced by HMAC. Reading K allows recomputation from block one and prediction through exhaustion. Reading S affects all domains of that operation. There is no backtracking resistance or within-operation compromise recovery. One leaked K need not reveal another under ideal PRF assumptions. Fresh independent OS roots are required for recovery in later operations once the read access ends. Iteration bounds in the high-level rejection samplers at artificial exhaustion remain open.

## Scope of this evidence

The Nettle address trace violates a secret-independent memory-access requirement during keyed processing. An adversary with local cache observation is outside an ideal black-box PRG argument. The public transcript can also contain application-confidential messages if an application signs data before publication. Assessment here treats the Fiat–Shamir inputs as public as specified in the study. End-to-end key generation and signing use variable-time upstream arithmetic. The functional tests, independent primitive oracle and timing measurements answer different questions. [Binary review and threat model](SECURITY_LIMITATIONS.md) · [Test evidence](TEST_REPORT.md)

## Entropy failure at the public API

On the tested glibc/Linux system the system-linked executable imports `getrandom`. The provider retries interruptions and collects the requested bytes, returning an error when acquisition fails. Domain initialization depends on successful root acquisition. In the upstream public KeyGen wrapper, key serialization still followed a failed protocol call. The validation branch returns the error before either caller buffer is written. Its test links a private entropy provider into a separate executable, checks a failed key generation, a successful fresh key generation, and a signing failure on that valid key. This evidence concerns initial root acquisition. Exhaustion in a downstream arithmetic retry loop remains a separate open issue. [Entropy provider](src/common/generic/randombytes_system.c) · [Public wrapper](src/sqisign.c) · [Regression](research/entropy_failure.c)

With a 48-byte HMAC key and a 19-byte label/domain message, the inner and outer inputs to the complete Streebog hash are 83 and 128 bytes. Counter blocks have 63 bytes. The shortest complete Streebog challenge transcript has 195 bytes (26 + 1 + 3 + 83 + 82). These lengths exclude complete-input equality across the three named uses. They do not bound dependencies between internal compression states or prove joint pseudorandomness. The typed caller regression compares normalized key and commitment fields, including the key hint, with an independently assembled transcript and checks the complete zero-extended scalar for both hash families.
