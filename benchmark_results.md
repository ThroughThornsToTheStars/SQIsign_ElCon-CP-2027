# SQIsign NIST-I с экспериментальным XOF на Стрибоге-512

Сравнивались два варианта официальной реализации `ref/lvl1` первого раунда NIST On-Ramp, тег `nist-v1`, коммит `28ff420dd012b64fdca87729ba172ef8683172b1`. Объекты получены через GitHub API и проверены по Git SHA-1 вплоть до корневого дерева и коммита. Выбор первого раунда сохраняет указанное в постановке ядро KLPT. [Официальные исходники](https://github.com/SQISign/the-sqisign/tree/28ff420dd012b64fdca87729ba172ef8683172b1)

## Производительность

Медианы 30 измерений на вариант, по одному вызову операции на измерение. Относительное изменение равно `100 × (медиана Стрибога / медиана SHAKE − 1)`. Для времени приведён приближённый 95%-й процентильный бутстреп-интервал с повторной выборкой 30 пар по номеру испытания, 10 000 реплик.

| Операция | SHAKE, мс | Стрибог, мс | Δ времени | 95% ДИ для Δ | SHAKE, такты | Стрибог, такты | Δ тактов |
|---|---:|---:|---:|---:|---:|---:|---:|
| KeyGen | 2301.98 | 2279.00 | -1.00% | [-4.29%, +0.64%] | 7 384 608 678.5 | 7 360 531 951.5 | -0.33% |
| Sign | 3131.40 | 3088.68 | -1.36% | [-5.43%, +6.37%] | 10 064 179 314.0 | 9 889 240 280.5 | -1.74% |
| Verify | 72.07 | 72.12 | +0.07% | [-3.72%, +4.13%] | 232 784 970.0 | 233 346 591.5 | +0.24% |

Все три интервала включают ноль. На этой выборке нельзя достоверно приписать замене хэша ускорение или замедление какой-либо из трёх операций.

## Методика

Intel Core i7-4770HQ, Linux 7.3.4-arch1-2, x86-64, GCC 16.2.1, GMP 6.3.0, GNU Nettle 4.0. Для обоих вариантов использовались `-O3 -DNDEBUG -std=gnu99 -funroll-loops -fvisibility=hidden`, реализация поля `fp_p1913.c`. Процесс закреплён за логическим CPU 2, управление частотой `intel_cpufreq/schedutil`. Замеры выполнены на работающей настольной системе.

Одна прогревочная пара исключена. В каждой из 30 последующих пар обе сборки начинают с одинакового 48-байтного seed штатного тестового AES-CTR-DRBG и одинакового 32-байтного сообщения. Каждый процесс заново генерирует ключ, подписывает сообщение и проверяет полученную подпись. Порядок сборок чередуется. В интервал Verify входит вызов публичного `sqisign_verify`. Контроль результата протокольного верификатора и проверка изменённого сообщения выполняются вне интервала.

В измерительном цикле каждый запуск дал полный набор счётчиков. Время измерено по `CLOCK_MONOTONIC_RAW`. Такты измерены непосредственно аппаратным счётчиком `PERF_COUNT_HW_CPU_CYCLES`, закреплённым за задачей, в пользовательском режиме. Данные также содержат отдельный столбец `tsc` со значениями счётчика меток времени. ## Хэширование и границы вывода

Функция `hash_to_challenge` этой редакции хэширует сериализованный j-инвариант и сообщение одним вызовом `SHAKE256`. В сборке NIST-I на x86-64 запрашиваются 32 байта (четыре 64-битных слова). Они помещаются в первый блок экспериментального XOF и поступают в прежнее преобразование скаляров. Многоблочный вывод проверен отдельным тестом. Генерация ключей не вызывает этот хэш, поэтому её измерения служат контролем разброса. Смена challenge способна изменить дальнейшие вычисления подписи и проверки. Проценты характеризуют операции схемы целиком на данном стенде. [Исходный код формирования challenge](https://github.com/SQISign/the-sqisign/blob/28ff420dd012b64fdca87729ba172ef8683172b1/src/protocols/ref/protocolsx/encode.c#L427)

Пусть `H` — Стрибог-512 в байтовом интерфейсе GNU Nettle, `D = H(input)`. Последовательные 64-байтовые блоки равны `H(D || BE32(i))`, где первый индекс равен 1. Кодирует счётчик сама обёртка. Неиспользованный хвост блока сохраняется между вызовами. Максимальная длина потока составляет `64 × (2³² − 1)` байт. Эта конструкция задана для эксперимента. В Р 1323565.1.022-2018 функции деривации используют ключевые преобразования, включая HMAC и NMAC. Испытания в этой работе оценивают функциональность и производительность. [Рекомендация ТК 26](https://tc26.ru/standarts/rekomendatsii-po-standartizatsii/r-1323565-1-022-2018-informatsionnaya-tekhnologiya-kriptograficheskaya-zashchita-informatsii-funktsii-vyrabotki-proizvodnogo-klyucha-.html)

## Проверки

- При независимой чистой сборке через CMake 4.5.0 (Ninja, Release) CTest успешно выполнил 16 проверок в каждой конфигурации. Выбраны тесты NIST-I и общей арифметики. В SHAKE-сборке полный KAT прошёл за 560,39 с, в сборке со Стрибогом прошёл тест `streebog_xof`. Описанные выше замеры производительности получены отдельным запуском стенда GNU Make.
- Базовая сборка SHAKE-256 прошла все 100 официальных KAT уровня I. Штатный `test/test_kat.c` для записей 0–99 файла `KAT/PQCsignKAT_782_lvl1.rsp` побайтно сверил открытый ключ, секретный ключ и подписанное сообщение, а затем восстановил исходное сообщение.
- Штатный `test/test_sqisign.c` завершился с кодом 0 для обеих сборок. В каждом измерении `protocols_verif` вернул 1, внешний `sqisign_verify` вернул 0, а для изменённого сообщения внешний API вернул 1.
- Встроенный `streebog_selftest()` сверяет оба официальных 512-битных вектора для сообщений длиной 63 и 72 байта. Байты сообщения и результата переведены из порядка записи RFC в порядок байтового API. Для проверки порядка байтов, счётчика и повторного squeeze тест также использует 192 байта, независимо вычисленные через libgcrypt. Для каждого из 193 разбиений вывод совпал. Отдельные проверки охватывают пустой вход, перенос счётчика с 255 на 256 и исчерпание 32-битного диапазона. [RFC 6986, раздел 10](https://www.rfc-editor.org/rfc/rfc6986.html#section-10)
- Сверка с тегом охватывает `ec`, `gf`, `id2iso`, `intbig`, `klpt`, `nistapi`, `precomp`, `protocols`, `quaternion`, `sqisign.c` и публичные заголовки ключей. В объекте формирования challenge ссылка на `SHAKE256` при включении флага заменяется ссылкой на `streebog_xof`. Размеры для NIST-I составляют 64 байта для открытого ключа, 782 для секретного и 177 для подписи.

## Воспроизведение

Команды выполняются в корне репозитория. Для замеров использовался GNU Make. Обе сборки также воспроизведены через CMake 4.5.0 и Ninja в режиме Release. Для запуска CTest с файлами KAT каталоги сборки в командах ниже расположены непосредственно в корне репозитория.

```sh
make -j4 -f experiment/Makefile test bench build/experiment/lvl1/shake/kat
make -j4 -f experiment/Makefile backend=streebog test bench build/experiment/lvl1/streebog/selftest
build/experiment/lvl1/shake/test_sqisign
build/experiment/lvl1/streebog/test_sqisign
build/experiment/lvl1/streebog/selftest
(cd build/experiment && lvl1/shake/kat)
python3 experiment/run.py 2 build/repeat.csv
python3 experiment/summarize.py build/repeat.csv
```

Чистая сборка и тесты CMake для параметров эксперимента, включая общие тесты целочисленной и кватернионной арифметики:

```sh
for profile in OFF ON; do
    dir="cmake-ref-$profile"
    cmake -S . -B "$dir" -G Ninja -DCMAKE_BUILD_TYPE=Release -DSQISIGN_BUILD_TYPE=ref -DUSE_STREEBOG="$profile" || exit 1
    cmake --build "$dir" -j4 || exit 1
    ctest --test-dir "$dir" -R 'lvl1|LVL1|streebog_xof|test_intbig|test_quaternion' -j3 --output-on-failure --no-tests=error || exit 1
done
```
