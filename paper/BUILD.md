# Сборка рукописи ElCon-CP

Из корня рабочей копии выполните `./paper/build.sh`. Конвертер читает файлы в порядке `sources` в `paper/manuscript.yaml`. Все пути к материалам отсчитываются от `paper/`. Результаты находятся в `paper/build/`.

| Файл | Назначение |
|---|---|
| CP2_Kretov_Adaptation.pdf | Экспорт Word-документа через LibreOffice Writer |
| manuscript.docx | Рабочий документ на основе шаблона организаторов |
| manuscript.tex | Представление содержания для сверки формул и текста |
| build.log | Команды, версии основных конвертеров и результат последней попытки |

Исходник шаблона — **Strict OOXML**. Сборка конвертирует его временную копию через Writer в Transitional OOXML, использует её как reference DOCX для Pandoc, восстанавливает именованные стили и непрерывные секции по геометрии образца, затем экспортирует документ через Writer. Образец и русские рекомендации в `template/` сохранены побайтно. Пагинация зависит от версии Writer и установленных шрифтов. Перед отправкой сравните рабочий DOCX с образцом, в том числе в Word, если подаётся Word-файл. Шаблон TeX организаторы в переданном комплекте не предоставили.

## Установка на Linux

Нужны Pandoc **3.1 или новее** (Figure AST, встроенный citeproc), LibreOffice Writer с фильтрами DOCX и PDF, Python 3.10+, PyYAML, lxml, Pillow, Poppler, Fontconfig, Bash, flock из util-linux. Нужен установленный по лицензии **Times New Roman**, включая обычное, жирное и курсивное начертания. Проверьте `fc-match 'Times New Roman'`. Для одинаковой пагинации оба автора должны пользоваться одинаковыми версиями Writer и шрифтов. Формулы для данной рукописи набраны текстом с индексами в Times New Roman. Неполное подразделение допускается только для рабочего экземпляра. Перед выпуском заполните department у обоих авторов. Сборка выводит версии Pandoc и Writer в журнал.

Для Arch Linux используйте `sudo pacman -S --needed pandoc-cli libreoffice-fresh python-yaml python-lxml python-pillow poppler fontconfig util-linux`. Для Debian с Pandoc 3.1+ подходят пакеты `pandoc libreoffice-writer python3-yaml python3-lxml python3-pil poppler-utils fontconfig util-linux`. В старых дистрибутивах проверьте версию `pandoc --version` до запуска. TeX Live для экспорта из Word не требуется. IEEE CSL включён локально. Его версия, авторство и лицензия указаны в `template/ieee.csl` (репозиторий citation-style-language/styles, файл ieee.csl).

## Работа авторов

- Текущая рукопись — один файл `manuscript_draft.md`, на основе локального черновика `326a07e`. Для нескольких файлов замените список `sources`, например на `[sections/01-introduction.md, sections/02-related-work.md]`, и перечислите остальные разделы в порядке чтения. Название и аннотация идут один раз в первом файле. Начните документ с заголовка `#`, разделы — с `## I. Introduction`, подразделы — с `###`. Аннотация начинается с `**Abstract—** `. Реестровый текст доступен в `REGISTERED_ABSTRACT.txt`.
- В `authors` укажите два словаря в порядке слева направо. Поля каждой записи — `name` (имя, инициал отчества, фамилия), `department`, `organization`, `location` (город и страна), `contact` (email или ORCID). В `keywords` укажите список английских ключевых слов. Пустые списки сохраняют возможность черновой сборки. Образцы имён и организаций из рекомендаций не являются данными авторов.
- Поддерживается стандартный Markdown Pandoc, включая списки, Unicode, `$x_i^2$` и блочную математику. Для нумерованного уравнения поместите блок `$$ … $$` в fenced div с атрибутами `{#eq:my-id .equation}`. Ссылка с автоматически вычисляемым номером — `[#](#eq:my-id)`. Для многострочных выражений используйте `aligned` и задавайте математически допустимые места переноса сами. Редактируйте только исходник, а не сгенерированный TeX.
- Для рисунка используйте отдельный абзац `![English caption](figures/plot.png){#fig:plot width=3.2in}` и ссылку `[#](#fig:plot)`. PNG, JPEG и одностраничные PDF поддерживаются. В Word вставляется представление PDF с разрешением 300 dpi. Исходные графики остаются векторными PDF в репозитории. Для Fig. 1 два исходных файла перечислены в `panels` и размещаются слева направо.
- Таблицы — обычные pipe tables. Для нумерации заключите таблицу с подписью `: Caption` в div с `{#tbl:my-id}`, ссылка — `[#](#tbl:my-id)`. Для размещения поперёк обеих колонок добавьте класс `.wide`, как у двух таблиц результатов. Отдельный div `{.wide}` подходит и для рисунка, и для длинной формулы. Остальной текст остаётся в двух колонках. При добавлении узкой таблицы проверьте ширину в Word и в PDF.
- Цитирование — `[@sqisign3]` или `[@sqisign3, Sec. 3.3]`. Источник добавляется в `references.bib` с уникальным ключом. Citeproc назначает номера по первому упоминанию и строит список с локальным стилем IEEE. Для пропусков в метаданных нужны сведения авторов. В исходной библиографии, например, спецификация SQIsign атрибутирована команде, а в ручном списке черновика указано «M. A. Aardal et al.». В имеющейся записи спецификации Hypericum нет года. При сверке ориентируйтесь на первоисточники.
- Рекомендации требуют английский текст, Abstract из 2–3 предложений, 3–6 страниц основного текста без шапки и библиографии, Times New Roman 24 pt для заголовка, 9 pt для блока авторов и Abstract, 10 pt для текста, 8 pt для подписей рисунков. Зарегистрированная аннотация длиннее рекомендации. Сборка не сокращает текст и сохраняет регистр букв в согласованном названии.

## Диагностика и очистка

Проверяются доступность файлов, создание PDF, структура базы BibTeX, ключи цитат и внутренние ссылки, уникальность меток и неизменность исходников. Отдельный временный профиль Writer исключает конфликт с открытым редактором. Артефакты последней успешной сборки заменяются после проверки нового PDF. При ошибке сначала прочитайте `build/build.log` и проверьте дату PDF. Сообщение о занятой сборке означает, что другой процесс работает в том же каталоге.

Poppler проверяет границы слов на каждой странице, наличие числовых значений таблиц и край видимого изображения страницы. Эти проверки не выявляют все внутренние наложения, неверные переносы и подстановки шрифтов. Пролистайте страницы в PDF при масштабе 100–150%, проверьте блок авторов, обе таблицы, подписи осей обеих панелей, три формулы, колонки и References. Лимит объёма считайте по основному тексту. Overfull/Underfull hbox относятся к компиляции TeX. В маршрут экспорта DOCX → PDF такая компиляция не входит.

Для очистки по завершении всех сборок удалите только `paper/build/`, затем запустите сборку снова. Команда из корня проекта — `rm -r -- paper/build`. Временные файлы, PDF и DOCX из build игнорируются Git.
